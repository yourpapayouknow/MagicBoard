- **Why（目的/背景）**：用户在 iOS 18.4 模拟器中测试完全正常，但在 iOS 16.6.1 实体设备上通过 TrollStore 安装后，调起键盘扩展立即崩溃（闪退）。用户要求排查原因（初拟是否调用了 iOS 16 以上 API），经证实并非 API 版本问题，而是 iOS 系统级 Jetsam 内存限制导致。
- **How（如何实现/决策过程）**：
  1. **排查 API 版本**：代码全域检索与符号扫描确认 Deployment Target 严格为 iOS 16.0，无任何 iOS 17/18 专属 API 调用，排除 API 兼容性问题。
  2. **锁定根本原因（Jetsam 物理内存超限）**：iOS 系统内核对 Keyboard Extension (`com.apple.keyboard-service`) 设置了极严格的物理内存上限（通常约为 30MB–48MB）。此前项目只打包了 YAML 明文码表，RimeEngine 在键盘视图加载 (`viewDidLoad`) 时启动了在线编译构建（`maintenance: true`），解析数十万行明文字典生成 `.table.bin` 和 `.prism.bin`，瞬间产生高达 ~194MB 的 Dirty RSS 内存峰值，触发操作系统内核 Jetsam 机制抛出 `SIGKILL (EXC_RESOURCE -> MEMLIMIT)` 强制终止。
  3. **解决方案**：在打包前采用离线预编译机制，将 7 种输入方案预编译好的二进制文件（`.table.bin`, `.prism.bin`, `.reverse.bin` 等，共计约 22MB）直接集成进扩展的 `RimeResources/build/` 目录；调整 `RimeEngine.swift` 配置 `prebuiltDataDir` 并设置 `maintenance: false, fullCheck: false`。Rime 直接通过 `mmap` 以只读 Clean Memory 映射字典文件，不再消耗 Extension 的 Dirty 内存配额，内存常驻仅在 15MB–25MB 之间，彻底远离 Jetsam 阈值。
  4. **版本升级与实机验收**：将版本号由 `1.0.0 (19)` 升级为 `1.0.1 (20)`，重新编译并打包 `MagicBoard.tipa`。用户在 iOS 16.6.1 实体设备上覆盖安装并验证，确认键盘秒开、候选词正常、无任何闪退。
